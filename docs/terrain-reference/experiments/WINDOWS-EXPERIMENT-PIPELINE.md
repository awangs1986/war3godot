# Windows 真机实验流水线（可复现）

> 目的：在 **Windows 原生** 环境完成"落笔 → 保存 → 抽 w3e → 逐字节对照"，用于补齐 G5/G6/G8。
> 全部通过 **Win32 消息**驱动，不依赖键盘盲打或坐标点菜单（本环境两者都不可靠）。

## 1. 启动

```powershell
$exe = "D:\games\W3R\war3r\Warcraft.III.R\_retail_\x86_64\World Editor.exe"
Start-Process -FilePath $exe -ArgumentList '-launch' -WorkingDirectory (Split-Path $exe)
```
- **必须带 `-launch`**：不带参数会在启动后立即退出（实测）
- 本机 EULA 已接受 ⇒ 不再弹欢迎框；工具面板会自动出现

## 2. 新建地图（零坐标）

```powershell
. D:\tools\menudrv.ps1        # GetMenu/GetMenuItemInfo/PostMessage 封装
$h = (Get-Process -Id $pid).MainWindowHandle
[M]::PostMessage($h, 0x0111, [IntPtr]1, [IntPtr]::Zero)   # 文件→创建新地图(N) 用 Ctrl+N 亦可
# 「创建新地图」对话框底部的确定按钮在 1280x800 下**不可见** ⇒ 用 Enter 接受默认 64×64
```

## 3. 保存地图（关键：三层对话框 + 一个陷阱）

菜单 ID（`GetMenuItemInfo` 读出的真实值）：

| 菜单项 | id |
|---|---|
| 保存地图(S) | **4** |
| 地图另存为...(A) | **5** |
| 荒芜地表(H)（察看菜单） | **517** |
| 工具→刷子大小(B) / 刷子形状(A) | 1282 / 1283 |
| 文件→创建新地图(N) | 0（用 Ctrl+N） |

流程：

1. `PostMessage(hMain, WM_COMMAND=0x0111, 5, 0)` → 触发另存为
2. **警告「有玩家的开始点未被放置。是否自动放置开始点？」**
   - 点 **否** ⇒ **保存被取消**（陷阱，实测）
   - 点 **是** ⇒ 继续（开始点与 w3e 无关，安全）
3. **提示「该地图仍使用默认名…」** → 点「确定」
4. `另存为` 对话框（class `#32770`）：
   - 文件名 `Edit`：对其 `WM_SETTEXT (0x000C)` 写完整路径
   - `保存(&S)` 按钮：`BM_CLICK (0x00F5)`
5. 标题栏变为 `[D:/tools/exp/E0.w3m]` 即成功

## 4. 抽取 w3e（mpyq，无需 listfile）

```python
import mpyq
a = mpyq.MPQArchive(r"D:\tools\exp\E0.w3m", listfile=False)
data = a.read_file(b'war3map.w3e')     # 29,644 字节，头 57334521 0b000000 = "W3E!" + version 11
```
注意：`a.files` 在 `listfile=False` 时为 `None`，**不能** `len()`；直接 `read_file` ✓

## 5. 实测踩坑清单

| 现象 | 原因 / 处理 |
|---|---|
| 不带 `-launch` 启动即退出 | 必须加 `-launch` |
| 点坐标 y=58 打开了「打开文档」 | 菜单栏坐标映射不可靠 ⇒ **一律用菜单 ID + WM_COMMAND** |
| `Ctrl+S` 后无文件、出现两个 ghost「警告」窗口 | 编辑器进入僵死态（窗口不响应 WM_CLOSE）⇒ 按 pid 强杀重启 |
| 另存为时选「否」 | 保存被**取消**，必须选「是」 |
| `mpyq` 报 `len(None)` | 用 `listfile=False` 时 `files` 为 None，直接 `read_file` |

- `D:\tools\exp\E0.w3e`（29,644 字节，version 11）⇒ 可直接与编辑后版本逐字节对照

## 7. 重启后握手序列（round 28–30 补齐，避免重复踩坑）

**现象**：强杀并 `-launch` 重启后，`Ctrl+N` / `保存` 均无效 ✗，窗口标题停在 `魔兽争霸III地图编辑器`（无地图）。

**原因**：重启后旧窗口句柄与焦点假设失效；且新实例启动后**不会自动新建地图**。

**正确握手顺序**：

```powershell
$np = Start-Process "…\World Editor.exe" -ArgumentList '-launch' -WorkingDirectory (Split-Path $exe) -PassThru
$Pid0 = $np.Id
# 1) 等主窗口出现（OsWindow，标题含「魔兽争霸III地图编辑器」），最长 60s
# 2) 枚举 [U]::Top($Pid0) 拿到 OsWindow 句柄 → ShowWindow(SW_MAXIMIZE) → SetForegroundWindow
# 3) 先在地图区点一下（例如 (400,400)）确保焦点在视口，再发 Ctrl+N
# 4) Ctrl+N 后等 2s，对话框标题应为「创建新地图」；按 Enter 接受默认（64×64）
# 5) 标题应变为「…[未命名的 1]」⇒ 握手成功
# 6) 首次保存走三层对话框：警告(开始点)→**必须选「是」**、提示(默认名)→确定、另存为→WM_SETTEXT 全文
#    路径 + BM_CLICK 保存；若出现「确认另存为」→ 选「是」→ **再点一次「保存」**
```

**保存是否真的写盘的唯一判据**：
```powershell
$h1 = (Get-FileHash $map).Hash; # 落笔前
# …落笔（标题应变脏）+ 保存…
$h2 = (Get-FileHash $map).Hash; # 保存后
if ($h1 -eq $h2) { "保存未写盘 ✗ —— 不要继续取数" }
```
⇒ 本轮 G5′/G6′ 正是因为 **`h1 == h2`（T1/T2 与 T0 逐字节相同）** 而拒绝把"脏标记变化"当作证据 ✓

## 8. 崩溃记录与操作纪律（round 27+ 追加）

### 8.1 事件

| 时间 | 事件 |
|---|---|
| 19:21:32 | `G0.w3m` 最后一次保存（19060 B；`war3map.w3e` 仍为标准 29644 B ✓） |
| 之后 | 堆叠出 3 个对话框：`提示`「该地图仍使用默认名…」×2、`警告`「该地图不再作为对战地图，因为：在无效位置有一个或多个的开始点」 |
| 清掉这些对话框的过程中 | 出现 **`World Editor has stopped working`** ⇒ 进程崩溃 ✗ |

### 8.2 判定

- 那三个对话框**不是错误** ✓：`默认名` 是保存时的例行提示，`开始点无效` 是因为我建的是空图、没放开始点 ⇒ 都是正常的保存确认 ✓
- 崩溃发生在**连续多轮"保存 → 弹窗 → 关弹窗"之后** ✗；`%LOCALAPPDATA%\CrashDumps` **没有** `World Editor` 的 minidump ✗
  （原因：我点掉了 WER 的「确定」，WER 对话框被关闭 ⇒ 可能因此未落盘 ✗）
- 事件日志里只有 18:06 的 `RADAR_PRE_LEAK_64`（内存泄漏报告，不是本次崩溃）✓
- **存档未损** ✓：`mpyq` 能正常读出 `war3map.w3e`，长度 29644 = 65×65×7 + 69 ✓

### 8.3 新增操作纪律

1. **一次会话只做一次保存**：连续多次 `保存` 会累积弹窗；每轮开始前先 `枚举并清空` 所有 `#32770` 对话框 ✓
2. **只对"仅确定"的对话框自动点确定**；出现 `是/否/取消` 一律停手人工判断 ✓（本轮已按此执行 ✓）
3. **崩溃后不要点 WER 的「确定」** —— 让它落完转储再关，否则拿不到 minidump ✗
4. 每轮操作后立即 `复制 + Get-FileHash` 记录存档，崩溃也不会丢证据 ✓（本轮 `G0/J1/J2/K1/K2` 都在 ✓）
5. 判定"落笔成功"**永远用存档字节**，不看标题脏标记、不看弹窗 ✓

## 9. 「覆盖请求」关不掉 —— 根因与修复（用户反馈）

### 9.1 事实

2026-10-17 的自动化里，`另存为` 覆盖已存在文件时弹出 **「确认另存为」**（`是/否`）✗。
我当时的纪律是「**只自动点『仅确定』的对话框，`是/否` 一律停手**」✓ ⇒ 于是该对话框**一直挂着** ✗，
最终**由用户手动关闭** ✓。

### 9.2 根因

把「安全」规则写成了**一律不点 `是`** ✗ —— 但"覆盖我们自己指定的输出路径"是**完全预期内**的动作 ✓，
不该和"是否继续危险操作"混为一谈 ✗。

### 9.3 修复：白名单助手 `tools/save-map.ps1`

| 对话框 | 处理 |
|---|---|
| `提示`「该地图仍使用默认名…」 | 确定 |
| `警告`「开始点无效 / 不再作为对战地图」 | 确定 |
| **`确认另存为`（或正文含「覆盖 / 已存在」）** | **是** ← 目标路径由我们自己指定 ✓ |
| 其它任何 `是/否/取消` 组合 | **不点**，返回 `NEEDS_HUMAN` 并打印按钮与正文 ✓ |

返回码：`SAVED` / `SAVED:<path>` / `NEEDS_HUMAN:<原因>` / `FAILED:<原因>`

用法：
```powershell
.\tools\save-map.ps1 -Pid 27644 -AsPath D:\tools\exp\X1.w3m   # 另存为（自动处理覆盖确认）
.\tools\save-map.ps1 -Pid 27644                              # 普通保存（菜单 ID 4）
```

### 9.4 同时修正的第二个坑

「另存为」对话框里有**两个 Edit**：一个是**地址栏**（top≈95），一个是**文件名框**（top≈372）✗。
脚本按 `Top -gt 300` 选文件名框 ✓（此前我误选地址栏 ⇒ 文件名写不进去 ✗）。

### 9.5 纪律更新

1. **预期内的确认要点**（覆盖自己指定的路径、默认名提示、开始点警告）✓
2. **预期外的确认一律停手**（关闭未保存修改、删除、覆盖**非本流程**的文件）✓
3. 任何返回值不是 `SAVED*` 时 **立即停止该轮实验**并上报，不要继续叠对话框 ✗

## 10. **重复保存会崩** —— 第二次崩溃已确认（硬发现）

### 10.1 两次崩溃的共同点

| 次序 | 触发 | 结果 |
|---|---|---|
| 第 1 次 | 连续多轮「保存 → 弹窗 → 关弹窗」（`G0.w3m` 19:21:32 之后） | `World Editor has stopped working` ✗ |
| 第 2 次 | 用 `save-map.ps1` 对**同一路径**连做两次「另存为」 | 又是 `World Editor has stopped working` ✗ |

共同点：**短时间内多次写盘**（间隔 < ~30 s），且每次都伴随 `开始点 / 默认名` 确认框；
两次均**未生成** `World Editor` 的 minidump ✗。

### 10.2 存档不受影响

| 文件 | 大小 | `war3map.w3e` |
|---|---|---|
| `G0.w3m` | 19060 B | **29644 B** ✓（= 65×65×7 + 69） |
| `S1.w3m` | 16822 B | **29644 B** ✓ |

⇒ 崩溃发生在保存**之后**（文件已完整落盘 ✓），没有产生半截存档 ✓

### 10.3 由此确定的实验协议（强制）

1. **一个编辑器会话最多写盘 1 次**；需要第 2 个存档点 ⇒ **重启编辑器**
2. 每次写盘前先**清空所有对话框**（`枚举 → 只处理白名单`）
3. 写盘后立刻 `复制 + Get-FileHash` 固化证据，再做下一次重启
4. 若返回 `FAILED:crashed` ⇒ **立即停止该轮**，不要再点任何窗口 ✓（避免再次阻止 WER 落盘）

### 10.4 `save-map.ps1` 的两处修正

- 排除非对话框窗口：标题匹配 `工具面板 | 进程` 的**不当作确认框** ✓（`进程` 是保存过程中的状态窗口，曾被误判为"未识别确认框"）
- 识别崩溃：标题匹配 `stopped working | 已停止工作` ⇒ 直接返回 `FAILED:crashed` ✓

### 10.5 这条发现对剩余实验的影响

任务 2 的四组纹理×荒芜实验需要 **4 个存档点** ⇒ 按 1 存档/会话 的协议**必须重启 4 次编辑器** ✓；
每次重启后要重新定位调色板句柄（控件句柄每次启动都变 ✓，见 `MAPPING.md §5`）。
因此这四组实验的脚本必须**自带"启动 → 定位 → 落笔 → 保存 → 取字节 → 关闭"**的一体化流程，不能靠跨轮手动接力 ✓。
