## 1. 悬崖连点（`cliff_repeat`）

**A 级来源**：`fixtures/base.w3e → fixtures/P_c+2_s3_x3.w3e`，点击角点 **(31,29)**，`L:2 ct:15`，连点 3 次

⇒ **规则（A）**：每向外一环，L 比内环**低 2 层**；有效半径 ≈ **4.5 角点**；`cliffType 15→1` 覆盖到 **r≈6**

### 1.2 实测：**+y 方向不对称**（关键未解点）

| 点 | 距离 | 该环其余点 | 该点异常 |
|---|---|---|---|

⇒ 效应在 **+y（南）方向延伸更远** ✗。**同一异常在深水重刷也出现**（见 §2）⇒ 怀疑是**一个共同成因**，不是笔刷各自的 bug ✓

### 1.3 未解点

1. `+y` 方向更远的成因（可能是坐标/形状中心偏移，也可能是官方对 `(x,y)` 的方向约定）
2. 单次「升高一层」与「升高两层」是否都按 +2 层推进（本 case 是 3 次共 +6，未分离单次增量）
3. `cliffVar` 的随机分布（实测 0→1/0→2，分布规律未测）

## 8. 关于「`+y` 方向不对称」的假设与判定实验（§1.2 / §2.1 的共同异常）

### 8.1 假设（推断，待实测）

圆形/环形掩码可能**以游标（连续坐标）为圆心**，而不是以角点为圆心。
若实验时鼠标落在角点格内偏南（`fy > 0.5`），圆心会整体南移约 `0.5` 角点 ⇒
现象正好是：**南侧多出一环、北侧少一环** ✓（与 §1.2 的 (31,33)=6、(31,34)(30,34)(32,34)=4 完全吻合）

**旁证**：`ghidra_27d450.c:105-112` 里两个 0/1 选择器来自**浮点坐标与 ≈0.5 的比较** ⇒ 官方确实用连续坐标做过判定 ✓
**反向证据**：坡道的 4 个亚格偏移（±0.25）**没有**改变集合 ⇒ 至少坡道的**3 共线/3×3 选择**不依赖亚格 ✓
⇒ 结论尚未成立：可能"**形状掩码**用游标圆心（受亚格影响）"，而"**轴向判定**用角点（不受亚格影响）" ✓

### 8.2 判定实验（两次会话，各 1 次写盘）

在官方编辑器里对**同一个角点**做「升高一层 ×3」，但鼠标分别落在该角点格内的
**北半（fy≈0.25）** 与 **南半（fy≈0.75）**：

- 若两次的层级剖面**整体平移约 1 角点** ⇒ 假设成立（掩码以游标为圆心）✓
- 若两次剖面**基本重合** ⇒ 假设否掉，需回代码解释 ✗

产出比对方式：`w3e_diff.py --only=layer` + 按距离分组统计（同 §1.1 的表）

### 8.3 若假设成立，对我们实现的影响

`TerrainBrush` 的形状掩码需接受**亚格偏移**（`subX/subY ∈ [0,1)`），圆心 = 角点 + 偏移；
而坡道的"轴向/3×3 判定"仍用角点整数坐标 ✓（与实测一致）

## 9. ★ 1.27 反编译交叉验证：水笔刷 `FUN_00603cc0`（B 级，地址可核）

**方法**：1.27 编辑器未加密 ⇒ 按 VA 切片包成最小 PE（`D:\tools\rev\mini_water_603cc0.exe`，保留 ImageBase 0x400000 / VA 0x603b80），
Ghidra 12.1.4 反编译成功（函数体 `0x603cc0–0x6040b8`，1017 B）。

### 9.1 参数含义（由代码用法确定）

| 参数 | 含义（证据） |
|---|---|
| `param_1` | **水模式**：`if (4 < param_1)` 才进入主体；分支里出现 `param_1 == 5` / `== 6` ⇒ **5=浅水、6=深水**（5 时多减 `[this+0x31c]`，见 `0x603db2`） |
| `param_2` | 角点/位置参数（经 `func_0x00575bb0(param_2,1,…)` 查索引） |
| `param_3` | **笔刷尺寸 size**（作为半径参与 `(param_3-1)²` 归一化，并传给后续两步） |
| `param_4` | **形状**：`local_28 = (param_4 == 0)` ⇒ **0 = 圆形**，非 0 = 方形 |
| `param_6` | 点击角点索引（`func_0x0056f620` ⇒ 再拆成 `y = idx/stride`、`x = idx%stride`，`stride = [this+0xb4]+1`） |

### 9.2 逐行关键事实

| 汇编 | 伪码 | 结论 |
|---|---|---|
| `0x603fbb` | `uStack_4c = uStack_4c \| 0x10` | **设水位标志 = 标志字 bit4 (`0x0010`)** ✓ 与 `CORRECTIONS.md` 标志位表一致 ✓ |
| `0x603d30` | `uVar3 = *(ushort*)(rec + 0xc) >> 4; … & 1` | 判"该角点是否已有水" 也是 **bit4** ✓ |
| `0x603d6b-0x603d7b` | `param_1==5 ⇒ dL=-2`；`param_1==6 ⇒ dL=-1`（**无水的角点**） | 浅/深水在"无水"时分别 −2 / −1 层（⚠ 与"深水=−2"的直觉相反 ⇒ 需与 1.32 存档核对哪个是深水） |
| `0x603dba-0x603dd2` | `iVar5 = (waterWorld − groundWorld)/128`；`if (waterWorld < groundWorld) iVar5 -= 1` | **有水的角点** ⇒ dL 由**水位差**算出，并向下取整 ✓ ⇒ 这就是"重刷深水"走的分支 ✓ |
| `0x603f89-0x603f98` | `if (1 < param_3) fVar11 /= (param_3-1)^2` | 距离按 **`(size−1)²` 归一化** ✓（与我们的 `R = size−1` 一致 ✓） |
| `0x603f9c-0x603fa9` | `if (local_28==0 \|\| fVar11 <= const)` | **圆形**：仅当归一化距离² ≤ 阈值才落笔；**方形**：整框都落笔 ✓ |
| `0x60405d-0x604068` | `func_0x0057e700(2, size + 2, param_4, 0, …)` | **整平（Plateau）用 `size + 2`** ✓ |
| `0x60408a` | `func_0x00574470(2, param_2, size, param_4, …)` | **悬崖（Cliff）用 `size`**（不加 2）✓ |
| `0x604079` | `[this+0x94c] = [this+0x770]`（= 目标层） | 悬崖步的目标层 = 前面算出的 `curL + dL` ✓ |
| `0x604057` | `[this+0x948] = [this+0x774]`（= 目标水面高度） | 整平步的 h0 = 目标水面高度 ✓ |

### 9.3 由本节直接得出的**实现结论**

1. **水位标志 = 标志字 bit4** ✓（我们在 w3e 侧用 `byte4 & 0x40`；两者是同一语义的两个表示，需在文档里并列写清 ✓）
2. **水掩码是圆（`(size−1)²` 归一化，阈值判定）**，方形时整框 ✓
3. **整平 size+2、悬崖 size** ✓ —— 这正好解释了我 §15 那次实验为什么"变差"：我当时把 **cliff** 改成了 `size+2` ✗，方向反了 ✓
4. 有水的角点，`dL` 由**水位差**算（不是固定 −depth）✓
