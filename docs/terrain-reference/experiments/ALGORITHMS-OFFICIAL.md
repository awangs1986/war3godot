## 8. 关于「`+y` 方向不对称」的假设与判定实验（§1.2 / §2.1 的共同异常）

### 8.1 假设（推断，待实测）

圆形/环形掩码可能**以游标（连续坐标）为圆心**，而不是以角点为圆心。
若实验时鼠标落在角点格内偏南（`fy > 0.5`），圆心会整体南移约 `0.5` 角点 ⇒
现象正好是：**南侧多出一环、北侧少一环** ✓（与 §1.2 的 (31,33)=6、(31,34)(30,34)(32,34)=4 完全吻合）

**旁证**：`ghidra_27d450.c:105-112` 里两个 0/1 选择器来自**浮点坐标与 ≈0.5 的比较** ⇒ 官方确实用连续坐标做过判定 ✓
**反向证据**：坡道的 4 个亚格偏移（±0.25）**没有**改变集合 ⇒ 至少坡道的**3 共线/3×3 选择**不依赖亚格 ✓
⇒ 结论尚未成立：可能"**形状掩码**用游标圆心（受亚格影响）"，而"**轴向判定**用角点（不受亚格影响）" ✓

### 8.2 判定实验（两次会话，各 1 次写盘）

在官方编辑器里对**同一个角点**做「升高一层 ×3」，但鼠标分别落在该角点格内的
**北半（fy≈0.25）** 与 **南半（fy≈0.75）**：

- 若两次的层级剖面**整体平移约 1 角点** ⇒ 假设成立（掩码以游标为圆心）✓
- 若两次剖面**基本重合** ⇒ 假设否掉，需回代码解释 ✗

产出比对方式：`w3e_diff.py --only=layer` + 按距离分组统计（同 §1.1 的表）

### 8.3 若假设成立，对我们实现的影响

`TerrainBrush` 的形状掩码需接受**亚格偏移**（`subX/subY ∈ [0,1)`），圆心 = 角点 + 偏移；
而坡道的"轴向/3×3 判定"仍用角点整数坐标 ✓（与实测一致）

## 10. 1.27 常量实测（B 级，地址可核；`D:\games\war3\WorldEdit.exe` 文件字节直读）

| 符号 | 地址 | 原始字节 | 值 | 作用 |
|---|---|---|---|---|
| `_DAT_007cb4bc` | `0x7CB4BC` | `0000803f` | **1.0f** | 圆形掩码阈值 ⇒ **归一化距离² ≤ 1.0** |
| `_DAT_0086b618` | `0x86B618` | `00000043` | **128.0f** | 世界高度 → 地形层数：`dL = Δworld / 128` |
| `_DAT_007e003c` | `0x7E003C` | `0000c045` | **6144.0f** | 水面高度位段 → 世界坐标的偏移 |
| `_DAT_007ed980` | `0x7ED980` | `00000045` | **2048.0f** | 水位编码：`raw = (world + 2048) * 4` |
| `_DAT_007ce50c` | `0x7CE50C` | `00008040` | **4.0f** | 同上（乘 4） |

### 10.1 由此确立的两条硬结论

1. **圆形笔刷半径 = `size − 1`** ✓
   因为掩码判定是 `dist² / (size−1)² ≤ 1.0`（`0x603f98` 归一化 + `0x603fa2` 比较 1.0）
   ⇒ 与我方实现的 `R = size − 1` **一致** ✓（此前的 `size/2` 是错的方向 ✗）

2. **水位 raw 编码 = `(worldHeight + 2048) × 4`** ✓
   代入实测：`wh = 8192` ⇒ world = `8192/4 − 2048 = 0` ⇒ **海平面 = 0** ✓
   ⇒ 深水用例里所有变化点 `wh=8192` 说明它们都是"海平面水位" ✓

### 10.2 我们实现里需要对照的两点

| 项 | 1.27（B 级） | 我方现状 | 处理 |
|---|---|---|---|
| 圆形半径 | `size − 1` | `size − 1` ✓ | 一致 ✓ |
| 整平尺寸 | `size + 2`（`0x604068`） | 曾改 `size+2` 到 **cliff** ✗ | 需改为 **cliff=size、plateau=size+2** ✓ |
| 有水角点的 dL | 由**水位差**算（`Δworld/128`，向下取整） | 固定 `−depth` ✗ | 需改为水位差 ✓ |
| 水位标志 | 标志字 **bit4 (0x10)** | w3e `byte4 & 0x40` ✓（同一语义另一种表示） | 文档并列写清 ✓ |

### 11.3 由本节得出的**实现结论**（这正是 20 项差异的根因方向）

1. **目标层必须按邻居夹取**：`target = max(neighborMin, min(Ltar, neighborMax))`，不是我现在的"直接按环填 Ltar" ✗
2. **传播是递归 + 一趟整框后处理**，不是单环 ✗
3. `ct` 的编码是 `mode<<4 | L`，所以"`ct 15→1`"实际是**模式从 0xF 变成 0**（低 4 位同为 1）✓
4. 圆形判定与水笔刷完全一致（R = size−1、阈值 1.0f）✓
