## 0. 方法学（重要，影响后续所有实验）

| 现象 | 实测结论 | 影响 |
|---|---|---|
| 视图是**透视投影**（非正交） | 屏幕 x 方向移动 72px ≈ 0~1 角点；y 方向 72px ≈ 1 角点 | 需要用"标记法"（同点刷 raise 再用数据反推角点）才能确定命中角点 |
| **不同笔刷/尺寸的热点可能差 1 角点** | 同屏幕点：cliff+1(s3) 命中 (31,32)，raise(s1) 命中 (31,31) | 连续试验必须用数据反推，不能假设"同屏幕点=同角点" |
| **无操作点击不产生撤销条目** | 坡道在平坦/无相邻高角点处点击 = 字节级无变化 | 用 `undo` 恢复状态不可靠；应"重开地图"或用数据校验 |

## 4. P0-2/P0-3 坡道（部分完成）

| 实验 | 结果 | 判定 |
|---|---|---|
| 坡道点在一层台阶旁的角点 | **写 3 个角点的 ramp 旗**：(31,30)、(31,31)、(31,32)（= 命中角点 + 其两侧邻居，共线 3 角） | ✅ 官方字节确认"3 角"规则 |
| 坡道点在无相邻高角点的平坦处 | 无 ramp（字节级无操作） | ✅ 确认"无相邻高角点 → 不写" |
| 坡道点在台阶旁另一侧 (32,32) | **未创建 ramp**（该角点确有 1 个高 1 层的 4 邻） | ⚠ 与"4 邻恰有一个高 1 层即建"的推断不符 → **规则细节待定**（可能还要求边方向/对侧等高） |
| 两层台阶拒绝 | **未取得有效数据**（两次 cliff+1 s1 命中到了相邻的两个角点，实际只有一层差） | ❌ 待重做 |

**待重做要点**：用"先建台阶→存档→用数据确认台阶角点→再用与台阶同一工具参数（或标记法）定位坡道命中角点"的流程，才能给出层差 2/凸角/凹角/地图边缘的可靠拒绝结论。
