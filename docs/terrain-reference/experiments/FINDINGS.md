## 2. 新发现的实现缺陷（已修复，且不留豁免）

| 缺陷 | 官方（证据） | 修复前实现 | 修复 |
|---|---|---|---|
| 悬崖变体取值范围越界 | **0..3**（V1） | `CliffVariation = Rng.Next(8)` → **会写 4..7** | 改为 `Rng.Next(4)`（`Cliff` 与 `Propagate` 两处） |

- 影响面：写出的 `variation` 字节 bit5-6 只占 2 位，写 4..7 会溢出到 bit7（地面 variation 的最高位），存档数值与官方不同。
- 修复后实测：40 次笔刷的变体最大值 **3**（此前 7）→ `B 层断言转"一致"`；A 层 45/45 不变。
- **未放豁免**：`known-differences.json` 里没有对应登记，一旦回归 harness 立刻失败。

## 3. 由官方存档反推出的悬崖规则（官方结果优先）

对 4 个单击悬崖 fixture（`cliff_c+2_s3` / `c+1_s3` / `c-1_s3`）逐点解码，得到**完全一致**的环剖面：

```text
足印 = 圆（R = size−1）→ 覆盖点层 L = L_点击点 + k     （s3：3×3 + 4 个轴向 d=2 点 = 13 点）
3×3 膨胀区 → 全部写所选悬崖类型 ct                     （s3：37 点，其中 24 点层未变、只改 ct）
8 邻按 [L−2, L+2] 钳制并逐环级联                        （重复点击时逐次生效）
```

- 三处均为官方字节直接产出，harness 在这 4 个用例上 **100% 一致**（150/150、148/148）。
- 实现与之一致 ✓（该规则本身**不是**本次的缺陷来源）。

## 4. `cliff_repeat` 那 20 点的定论（已从"未决"升级为**已测定的输入问题**）

对 `P_c+2_s3_x3`（recorded：点 (31,29)、+2、s3、重复 3 次）做**反演搜索**（以官方存档为目标，重放实现规则）：

| 搜索 | 结果 |
|---|---|
| 点击点候选（±5 邻域，3 次同点） | **(31,29) 最优 68/85**，次优 (31,30) 仅 40/85 → **点击点正确，"光标偏移"假设被否掉** |
| 施加次数 N=1..8 | **N=3 最优（68/85）**；N=1/2/4/5/6 均 ≤ 68/85 → 次数也正确 |
| 3 次点击序列全空间（25³ = 15625） | **0 组达到 85/85**，最佳 77/85（序列 `(33,31)→(31,31)→(31,29)`，即**末端带拖动**） |

**结论**：官方那 85 个改动点**无法由"3 次点击"复现**，真实操作含拖动/更多次施加，而该用例的 `note` 自述"命中角点未记录…未证实"。
→ 这 20 点在 `known-differences.json` 中**保持"未决"**，但原因已改为**实测结论**（不再是"疑似"），并把所需实验指明为 **P0-1（同角点重复施加）+ P0-5（悬崖变体与传播）**，且新增要求：**必须记录完整拖动轨迹与每个施加时刻**。
