## 5. G6 坡道判定：已从代码读出，但**方向约定未定**（本轮结论）

`ghidra_27d450.c` 行 121-205 给出完整判定（B 级）：

| 步骤 | 代码位置 | 内容 |
|---|---|---|
| 1 | L102-120 | 由落点的**子角格小数位置**选出点击方向（`bVar7`/`bVar8`），再读该方向两个相邻角点与对角角点的高度 |
| 2 | L121-127 | `|d1|`、`|d2|`：两个相邻方向相对点击角点的层高差绝对值 |
| 3 | L162-169 | `|d1|+|d2| == 1` → **3 共线**（沿差 1 的轴，点击角点为中点），`lVar34 = 3` |
| 4 | L129-131, L171-187 | `|d1|==1 && |d2|==1` 且 **对角角点高度 ≠ 点击点** → **3×3**，`lVar34 = 9`；对角等高则**放弃** |
| 5 | L131/L134/L172 | 其余情况**不落笔** |
| 6 | L192-205 | 集合内层高跨度 `max-min < 2`，否则放弃 |
| 7 | L229-241 | 逐角点 `bit1 == invert` 跳过；`invert=1` 置位 / `invert=0` 清位 |

**这解释了 R32 的反例**：Y8B(32,32) 落在"对角情形 + 对角角点等高"⇒ 官方按 L129-131 直接放弃，所以"恰有一个高 1 层 4 邻"并不足以推出会写 ramp ⇒ 旧表述不充分 ✓（已由代码证实，不再是猜测）。

**未完成部分（明确阻塞）**：步骤 1 的"点击方向"由**像素落点的子角格偏移**决定；本工程的自动回归在**固定像素**落笔，
该偏移的符号（`sx, sy ∈ {±1}²`）**没有实测确定**。用 `+x/+y` 代入后 ramp 层匹配率由 ~66% 掉到 18%，
说明该假设错误 ⇒ **实现改动已回退**，不保留猜出来的方向。

**下一步要做的实验（唯一解）**：在同一角点周围 4 个象限各取一个稳定像素落笔（共 4 次），
记录官方写出的角点集合方向 ⇒ 直接读出 `(sx, sy)`；随后把 L121-187 的规则按该约定实现，再用现有 13 条 ramp 用例验收。

## 6. G7 深水再点：机制已解释（B 级）

`ghidra_314880.c`（水刷 `FUN_140314880`，1294 条指令）：

| 步骤 | 位置 | 内容 |
|---|---|---|
| 门 | L55-56 | `FUN_14026c340(map,pos,1) != -1` 且笔刷种类 `> 4`（5/6 = 深/浅） |
| 水位 | L66-96 | 角点**尚无水**：`水面 = 地面h + k`（kind5→−2、kind6→−1）；角点**已有水**：由**现有水面字段**（`puVar13[1] >> 0x12`）重算，浅水另减 `map+0x4cc` |
| 足印 | L109-121, L145-148 | 以命中角点为中心的方形窗口 + **圆形衰减** `dist² ≤ size²`（`param_5 != 0` 时取整窗） |
| 写入 | L152, L155-156 | `flags |= 0x10`（置 water 位）；`[+4] = (idx & 0x3ffff) | (水面高度 << 0x12)` |
| 尾处理 | L173, L176 | 附加 pass；把本次水面高度存为 `map+0x94c` |
| **额外两遍** | **L181, L187** | `FUN_140276110(map, 2, size+2, …)`（**+2 尺寸**的层处理 ⇒ R14「水笔刷含整平」的来源）；**`FUN_14026a480(map, 2, pos, size)` = 悬崖层函数** |

⇒ **深水再点不是空操作**的原因有两个，且都可从代码读出：
1. 已有水时水位按**现有水面**重算（而非地面高度），与足迹内其他角点产生差；
2. 无论是否已水，末尾都会跑 **size+2 的层处理** 与 **悬崖层 pass**，从而改写足迹内/外的 `L` 与 `ct`。
   这与实测的 23 点构成（L 5 / water 5 / ct 7，其余为 cv）一致，无需再假设"随机行为"。

## 8. G3 补充：`ct`（悬崖类型）由层处理的直方图分支写入（B 级）

- `ghidra_26a480.c`（悬崖层 `FUN_14026a480`，1995 条指令）
  - L77-79：门 `FUN_14026c340(...) != -1` 且 `param_2 < 5`（0..4 = 五种悬崖操作）
  - L196-217：对足迹内角点取 `(byte[+0xa] & 0xf)` 的高度差 → **高度直方图** `puStack_178[h]++`，
    然后 `[+0xa] = (h & 0xf) | (kind << 4)`（L216-217）⇒ **写悬崖类型（高 4 位），层（低 4 位）保留**
  - L243：另一分支同样的 4 位类型写入
- `ghidra_276110.c`（水刷的 size+2 pass，2727 条指令）

## 11. G8 的真缺口：现有用例**没有比对 blight 位**

`Y7_blight_s3 → Y7_blight_tex1` 的对照字段只有 `tex`（harness 输出：`| texture | Y7_blight_s3 → Y7_blight_tex1 | tex | 13 / 13 |`），
**flags（含 bit2=blight）不在比对范围内** ⇒ 即使实现不清 blight 也会"通过"。

而 `ghidra_286a60.c:190,192` 已给出 **B 级**证据（`uVar6 = 0xfffb` → `auStack_d0._12_2_ &= uVar6`）。

**⚠ 自我修正（同日核对）**：把对照字段扩为 `tex,flags` **仍不足以**判定——
该用例自带 `note: "…**未落在荒芜点上**"`，且 `Y7_blight_s3` 的荒芜 13 点在 (29..33, 30..34)，
而本次落笔质心是 (23,26)，**两者不重叠** ⇒ 即便加了 blight 比对也是**空断言**。

因此 G8 需要**两个条件同时满足**：
1. harness 的 `texture` 字段集加上 `flags`（或 blight 位）；
2. **重新做一次官方实验**：先把荒芜落在某个角点，再在**同一角点**上用纹理落笔，并把命中角点记录下来。
   （旧归档不可复用——这是 R11 降级的直接原因。）

其它需要真机的剩余缺口同理：G5（边界移除）、G6（坡道方向标定）。

## 14. G5 边界：A 级官方数据（本轮真机产出）

**通道**：纹理刷的特殊条目 —— `BM_CLICK 264570` ⇒ `应用纹理: 边界`；`BM_CLICK 330108` ⇒ `应用纹理: 去除边界`
（不是 Shift，是独立模式）。落笔点必须在地图视口内（实测 `(800,500)` 生效；`(620,380)` 在视口外，标题不变脏）。

**实验**：`E0.w3m`（64×64 新建图）→ 保存复制为 `C0.w3m` → 放置边界后保存复制 `C1.w3m` → 移除边界后保存复制 `C2.w3m`
（保存用 `WM_COMMAND 4`，只处理「提示：默认地图名」对话框；**完全避开另存为对话框**）。

**w3e 逐角点对照**（`mpyq` 抽取，`war3map.w3e` v11，9,644…=29644 字节）：

| 比较 | 变化角点 | 变化字节位（0..6） |
|---|---|---|
| C0 → C1（放置） | **9** | [4, 5, 6] |
| C1 → C2（移除） | **7** | [4, 5, 6] |
| C0 → C2（净） | 12 | [5, 6] |

集合关系：**移除 ∩ 放置 = 4**、**放置 − 移除 = 5**、**移除 − 放置 = 3**

样本（`(x,y) 前 → 后`，十六进制 7 字节）：

```
(62,28) 00200020804810 -> 00200020002810     ← 移除
(62,29) 00200020000012 -> 00200020004012     ← 移除
(60,27) 00200020000cf2 -> 00200020002c12     ← 放置（byte5 0x0c→0x2c = 置 0x20；byte6 0xf2→0x12）
(62,28) 002000200008f2 -> 00200020804810     ← 放置（该角点还被写入 0x8048，需进一步归类）
```

**结论（A 级，可直接引用）**：
1. 边界刷的**落笔集合与清除集合不对称**（9 vs 7，交集仅 4）⇒ 实现里若假设"移除 = 放置的镜像"即错误。
2. 放置/移除都集中在**角点尾部 3 字节**（[4][5][6]），其中 **byte[5] 的 0x20 位**随放置置位、随移除清除。
3. 净变化 12 点，且 `(62,28)` 放置时被写入 `0x8048`（byte4-5），说明边界刷**还附带其它字段写入**，需单独归类（下一轮）。

**未决（下一轮）**：
- `(62,28)` 的 `0x8048` 语义（哪一位是边界、哪一位是别的标记）
- 为什么"放置 9 / 移除 7"不对称（是否与足迹圆形衰减 + 边界只在**角点可达**集合上生效有关）
- 需要把该实验接入 `cases.json`（fixture：`C0/C1/C2.w3e` + 两条案例），并让 harness 比对 `flags`/边界位

### 14.1 位级分解（离线，基于已归档 C0/C1/C2）

| 方向 | 字节位翻转（`byte[位] bitN 方向 ×次数`） |
|---|---|
| 放置（9 点） | `byte[6] bit5 clr ×9`、`bit6 clr ×9`、`bit7 clr ×9`、`byte[6] bit1 clr ×1`、`byte[5] bit5 set ×4`、`byte[5] bit6 set ×2`、`byte[4] bit7 set ×1` |
| 移除（7 点） | `byte[6] bit5/6/7 clr ×3`、`byte[5] bit5 set ×3 / clr ×1`、`byte[5] bit6 set ×2 / clr ×1`、`byte[4] bit7 clr ×1` |

**可引用结论**：
1. 放置边界的主效果是 **清 `byte[6]` 的高 3 位**（样本 `0xf2 → 0x12`，即高 4 位 `0xf → 0x1`，bit4 保留）并**置 `byte[5]` 的 0x20 / 0x40 位**；
   移除时 `byte[5]` 的这两位**不是简单取反**（有 set 也有 clr，且只在 3 个点上发生）⇒ 再次印证"移除 ≠ 放置的镜像"。
2. `byte[4] bit7` 只在**单个**角点上被 set（放置）/ clr（移除）⇒ 属"额外标记"，与边界的批量写入不是同一机制（正是 §14 里 `0x8048` 的来源）。

### 14.2 未决：w3e 角点的遍历序（x-major 还是 y-major）

用 `i = y*W + x` 反解坐标时，两个集合出现 **`x=0` 与 `x=63` 两个簇**，且放置集合里有一个 **半径 54.9 的离群点** ✗。
这与"单次圆形落笔应为一簇"矛盾 ⇒ 说明我的坐标反解可能是错的（w3e 很可能按 **x-major**：`i = x*H + y`）。

**下一轮先解决这一条**（用 C0/C1/C2 的集合形状反解：两种序各算一次连通性/半径分布，取能给出"单簇 + 单调半径"的那个），
在此之前**不引用任何坐标**，只引用位级与计数结论。

### 14.3 坐标序判定：**两个候选假设都被否定**（本轮结论）

用**已验证的用例元数据**做判据：`base → T_tex1_s3` 的落笔点为 `cx=31, cy=32`，官方改动 **13** 个角点（harness 报 `13/13`）。

| 项 | 结果 |
|---|---|
| 文件尺寸 | `base.w3e` = 29,644 字节；`29644 = 972 + 4096×7` **精确整除** ⇒ 头 972、64×64、7 字节/角点 ✓ |
| 变化角点数 | **13** ✓（与 harness 一致） |
| 序 A `i = y*W + x` | 质心 **(47.23, 30.23)**，与 (31,32) 距离 **16.33** ✗ |
| 序 B `i = x*W + y` | 质心 **(30.23, 47.23)**，与 (31,32) 距离 **15.25** ✗ |

**结论**：两种遍历序**都不能**把索引还原成案例里的 `(cx,cy)`；两者互为转置、且都偏离约 16 格，
说明 `cases.json` 的 `cx/cy` 与"角点索引"之间**不是单纯的转置关系**（可能含偏移/翻转/坐标口径差异，不能靠猜）。

**正解方法（下一轮执行，纯离线）**：取 ≥3 条"落笔点已知"的用例
（如 `T_tex1_s3`(31,32)、`X1_h_click1`、`Y10_ramp_made` 等），对每条算出变化角点集合的索引，
用最小二乘拟合仿射映射 `(x,y) = A·(i//W, i%W) + b`（A 限 8 种整数正交变换 + 平移），
取**同时满足全部用例**的那一组。在此之前**不引用任何坐标**，只引用计数与位级结论（§14、§14.1）。
