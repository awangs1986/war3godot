# 1.32 实验计划（官方结果优先保存，逐坐标逐字段对照）

> 目标：**先把官方编辑器的结果原样保存下来**，再把与现有实现的每一处不一致逐点列出来，作为独立判断依据。
> 原则：任何一处"说不清是笔刷写入问题还是渲染问题"的差异，**保持未决**（登记在 `known-differences.json`，状态 `未决`），禁止算作通过，也禁止用实现去反推官方行为。
>
> 相关文件：`CASE-FORMAT.md`（用例字段与目录规范）｜`known-differences.json`（未决差异登记）｜`cases.json`（已收录用例）｜`results.md`（预期结果）

---

## 0. 实验环境固定项（每个用例都要记）

| 项 | 说明 |
|---|---|
| 编辑器版本 | `World Editor.exe` 的 ProductVersion（当前基线 **1.32.10.18820 (f1d8377869)**）；若换版本必须整批重做 |
| 客户端/资源版本 | 客户端构建号 + `Data` 目录版本（`Launcher.db` / CASC build），用于判断贴图/模型是否变化 |
| tileset | 地图的 `Tileset` 与 `GroundTilesets`/`CliffTilesets`（**水面偏移、悬崖类型映射都随 tileset 变**，至少要覆盖 `L`（Lordaeron 类）与 `A`（Ashenvale 类）两种） |
| 编辑器配置改动 | 任何改过的 `MiscData` / INI（MaxSlope、MaxHeight/MinHeight、平滑权重、水面偏移等）；**没改也要写"未改"** |
| 地图基准 | 每次实验从同一张基准图开始（记录基准图文件名与它的 `w3e` 哈希），避免基准漂移 |
| 操作输入 | 点击/拖动的**屏幕坐标 + 地图格坐标**、按住时长、是否移动、修饰键（Shift / 右键 / 擦除） |

## 1. 用例记录规范（每个用例必须齐全）

每个用例落成**一个目录**（规范见 `CASE-FORMAT.md`），至少包含：

```
experiments/<用例号>-<算法>-<尺寸><形状>-<动作>/
├── meta.json          # 工具/尺寸/形状/修饰键/点击拖动步骤/tileset/版本/配置改动
├── before.w3e         # 操作前（从编辑器存出，或从基准图导出）
├── after.w3e          # 操作后（官方编辑器存出，原样）
├── patch.md           # 逐字段差异：坐标 (x,y) + 字段 + 官方值 + 现实现值
├── fields.tsv         # 机器可读的逐点差异（便于 harness 直接吃）
└── shots/             # 需要看渲染的用例才放：同视角 before/after 截图（近景：悬崖底边/顶边/拐角/岸边）
```

**逐字段差异**必须至少覆盖这些字段：`h`(地面高度 raw)、`L`(悬崖层)、`ct`(悬崖类型/纹理)、`cw`(悬崖变体 0..3)、`tex`(地面纹理)、`var`(ground variation)、`ramp`、`water`、`w`(水面高度 raw)、`blight`、`bound`。

> 只给"匹配数量/匹配率"不算结果；**必须给到 `(x,y) 字段 官方值 vs 实现值`**，否则该用例视为未完成。

## 2. 实验清单（P0 优先）

### 2.1 P0-1 同一角点是否重复施加 ★首批五组之一

| | |
|---|---|
| 目的 | 分清"一次笔画内的多帧"与"松开后再次点击"是否等价；确认官方是否对同一点重复叠加 |
| 步骤 | 升高 s1：① 单击 ② 原地按住 2 秒 ③ 同角点内轻微移动（±1 像素量级，仍落在同一格） ④ 移到邻点再返回原点 |
| 记录 | 每一步的**高度增量**（raw 与层）；按住时长；是否发生第二次施加；松开前后差分 |
| 判定 | 若官方单击增量 = 2×实现单击增量，说明官方一次按压含两次施加（或按住期间连续施加） |

### 2.2 P0-2 坡道创建与移除 ★（与 P0-3 合并为"坡道移除"组）

| | |
|---|---|
| 目的 | 确认坡道标志的**完整坐标集合**，以及"点哪里能建/能撤" |
| 步骤 | 造一条四方向的**一层悬崖**；分别在低侧、高侧、坡道中间点击；再测 Shift 点击、右键点击 |
| 记录 | `ramp` 标志的完整坐标集合；层级 `L` 与贴图 `tex/ct` 是否同时变化；失败时是否**整笔无操作** |
| 判定 | 是否存在"部分写入的残缺坡道"（这是最需要盯的失败形态） |

### 2.3 P0-3 坡道拒绝条件

| | |
|---|---|
| 目的 | 边界条件：两层差、凸角、凹角、地图边缘、混合邻域（一侧 +1、另一侧 +2） |
| 步骤 | 每种邻域各点一次坡道；每种情况独立存档 |
| 记录 | 是否完全无操作（`after.w3e` 与 `before.w3e` 逐字节比较）；是否出现残缺坡道 |
| 判定 | 拒绝必须是"整笔拒绝"，不得留下半成品 |

### 2.4 P0-4 纹理覆盖荒芜 ★（"纹理清荒芜"组）

| | |
|---|---|
| 目的 | 纹理刷是否会清掉 `blight`；Shift 点击是否不同 |
| 步骤 | 先画荒芜（s3）→ 再用**原纹理**覆盖 → 再用**另一纹理**覆盖（各含普通点击与 Shift 点击） |
| 记录 | `blight`、`groundTexture`、`groundVariation` 三个字段的逐点值 |
| 判定 | 若官方清 blight 而实现不清（或反之），是一处**必须修**的行为差异 |

### 2.5 P0-5 悬崖变体范围与传播 ★（"悬崖变体与传播"组）

| | |
|---|---|
| 目的 | 变体（variation）取值范围与传播区内容；确认 1.32 是 `Rng(0,3)<<5`（2 位）还是别的 |
| 步骤 | 圆形 s1、s3：单次 +2；**同点连续 +2**；每次单独存档 |
| 记录 | 覆盖区 / 外扩区 / 传播区**各自**的层级、类型、变体；变体是否出现 4~7（若出现说明不止 2 位） |
| 判定 | 变体分布是判据关键；同时对照 `known-differences.json` 里 `cliff_repeat` 那批未决点 |

### 2.6 P0-6 已有水面的笔刷行为 ★（"已有水面操作"组）

| | |
|---|---|
| 目的 | 浅水→浅水、浅水→深水、深水→浅水、深水→深水 各自是否继续降层、水面是否保留 |
| 步骤 | 分别在**平地 / 斜坡 / 台地**做；至少比较 **L 与 A 两种 tileset** |
| 记录 | `L`、`water`、`w`(水面高度)、`tex`、`ct`；岸边（水陆交界）的修改范围 |
| 判定 | 水位偏移是否随 tileset 变（这是 `Water.slk` 的直接判据） |

### 2.7 P0-7 传播范围与刷新

| | |
|---|---|
| 目的 | 陡坡上整平/平滑、连续升高两层之后，**笔刷外最远修改点**在哪；重开地图后是否一致 |
| 步骤 | 每步截图 + 存档；然后**关闭并重新打开地图**再看一次 |
| 记录 | 外扩点到笔刷边缘的距离；重开前后差分；有无残留方块/旧贴图 |
| 判定 | 若重开前后不一致 → 属于渲染/缓存问题，而非笔刷写入问题（要分开归因） |

### 2.8 P1-1 Shift 与形状规则

升高/降低/整平/噪声/平滑/水，各测圆形/方形 s3，带与不带 Shift：记录**实际覆盖集合**与反向效果；特别确认 Shift 平滑。

### 2.9 P1-2 荒芜外圈概率

同一基准图、同一点画 s1 荒芜，**撤销后重复 ≥100 次**；再测水中心/岸边/悬崖旁。记录每个相对坐标改变的次数与改成哪种纹理；若已找到配置表，**附表项**。

### 2.10 P1-3 高度与层级极限

层 0 降低、层 15 升高；接近高度上下限时升降、整平、放水。记录是**整笔拒绝**还是**部分写入**；`类型/变体/水标志` 是否被顺带改掉。

## 4. 复杂地形"方块问题"专项小地图

单独做一张小地图，逐步保存，**每步都拍照**（近景：悬崖底边、顶边、拐角、岸边）：

```
平地图
  → 一次升高两层
    → 在悬崖附近制造连续起伏
      → 刷两种地表
        → 在旁边放浅水
```

- 每步：保存 `w3e` + 同视角截图 + 记录坐标与工具参数。
- 另用**一层悬崖**再测一次坡道：便于区分
  - **笔刷写入问题**（`w3e` 里字段就不对）
  - **渲染问题**（`w3e` 字段正确，但画面上出现方块/接缝）
- 判定口径：`w3e` 正确而画面错 → 记入渲染问题，附同视角截图；`w3e` 就错 → 记入写入问题，走 `known-differences.json`。

## 5. 与验证程序的分工

| 环节 | 负责方 |
|---|---|
| 采集官方结果（before/after `w3e`、截图、元数据） | 人工/脚本按 §1 目录规范落盘 |
| 逐坐标逐字段对照、缺口报告、未决登记 | `standalone/W3EditorOfficialTest`（`dotnet run`） |
| 判定"通过" | 只有 **A 层（官方存档逐点一致）** 且无未登记差异；B/C 层不能替代 A 层 |

三层证据的含义（**不可合并成一个"还原率"**）：

- **A 官方存档已验证**：与官方 `.w3e` 逐坐标逐字段对照的结果（唯一能判"对"的证据）
- **B 二进制分析支持**：从反编译得到的常量/行为（有函数地址，但**不等于**官方运行时行为）
- **C 实现自检**：fixture 未覆盖的语义与行为快照（只记录现状，不作为通过依据）
