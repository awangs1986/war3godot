## 0. 术语与数据模型

| 概念 | 含义 |
|---|---|
| 角点 (corner / tilepoint) | 网格顶点，`.w3e` 中每个角点 **7 字节**（v11）/ **8 字节**（v12+） |
| 图块 (tile) | 由 **4 个角点** (bl, br, tl, tr) 围成的一个地形方块 |
| 层 (layer) | 悬崖造成的高度分层：`层高 = 128`（世界单位），同时决定该角点的贴图应使用哪种悬崖过渡 |
| 纹理 (ground texture) | 每角点地面纹理编号（v11: 4 位 0–15；v12: 6 位 0–63） |
| 悬崖字节 | `(悬崖纹理 << 4) | 悬崖层`（v11，见 §1） |

### 1. `.w3e` 角点字段（v11，7 字节）**[存档]**

| 偏移 | 类型 | 含义 |
|---|---|---|
| +0 | int16 | 地面高度 raw：**世界高度 = (raw − 8192) × 0.25**；层高 = `层 × 128` |
| +2 | uint16 | 低 14 位 = 水面 raw（同 8192 基准，**绝对水面高度**，不是水深）；bit14 = 地图边界标志（`MapEdge`） |
| +4 | uint8 | 低 4 位 = 地面纹理编号；bit4 = **斜坡(Ramp)**；bit5 = **枯萎(Blight)**；bit6/7 预留 |
| +5 | uint8 | 地面纹理变化 (variation) |
| +6 | uint8 | **悬崖字节**：低 4 位 = 悬崖层(0–15)；高 4 位 = 悬崖类型/纹理编号 |

> Undead03 实测：悬崖字节只出现 `0x0?`(类型 0) 与 `0x1?`(类型 1)，层位分布 **{2:2348, 3:663, 4:12504, 5:641, 6:3042, 7:1566, 8:4, 9:1}** ✓ 与 `cliffTilesets=['CLdi','CLgr']` 的 2 种类型一致 **[存档]**。

### 2. 编辑器内存中的角点记录（28 字节步长）**[代码]**

```
角点数组指针 = [map + 0x188]      步长 = 0x1C (28)
索引        = y * ([map+0xf4] + 1) + x      // [map+0xf4]=宽(tiles), [map+0xf8]=高
+0x00 dword : 地面高度 raw（低 14 位）+ 水/边标志位
+0x0a byte  : 纹理/斜坡/枯萎/悬崖位
解码 raw→世界: ((raw & 0x3fff) | 0x22c000) << 9 − 6144.0   // == (raw−8192)*0.25
编码 世界→raw: (h + 2048.0) * 4.0
纹理层高度偏移 : (纹理字节 & 0xf) * 128.0 − 256.0
```

## 2.5 分块（Chunk）组织 —— 1.32 内存模型 **[代码: FUN_140263b00]**

```
1 个 chunk = 4×4 tiles = 512 × 512 世界单位
世界坐标 → chunk:  cx = (worldX − [map+0x100]) * 0.001953125      // 1/512
                   cy = (worldY − [map+0xfc])  * 0.001953125
每块 tiles 数:      ([map+0xf4] − 1) >> 2      // 宽；高同理 ([map+0xf8]−1)>>2
chunk 索引:         (chunksPerRow + 1) * cy + cx
chunk 结构指针:     idx * 0xFD8 + [map+0x1d0]   // ★ 块结构步长 = 4056 字节
```
- 这也是为什么按"整行 65 个角点"在全内存里搜是搜不到的：**角点数据按 4×4 块分布，块间有 0xFD8−5×5×0x1C 的额外元数据**。
- 角点 32 位头字段里还编码了**两个 9 位层高域**（步进 128 世界单位），1.32 用浮点位技巧解码（`FUN_140263b00`）：
```
layerA = (float)(((dword & 0x7fc000)  | 0x47800000)) - 98304.0
layerB = (float)((((dword >> 0x17)) | 0x11e00) << 0xe) - 98304.0
```
  即内存中每角点同时保有 **地面高度（低 14 位，0.25 粒度）+ 两层"层高"（9 位，128 粒度）** —— 与 `.w3e` 里"地面高度 + 水位/悬崖层"两套数据对应，但编辑器额外把**层高**独立编码，用于悬崖/斜坡的快速拼接判定。
- 图块查询时的容差：`±((层偏移) * 128.0 + 1.0)`（构造 4 个角点高度时用）。

---


```
最终高度(角点) = 地面高度(GroundHeight) + 层高(LayerHeight) − 2.0     // 单位：tile（1 tile = 128 世界单位）
```

- 层高来自悬崖层：`层高 = 角点所属层 × 1.0`（tile 单位），即相邻层差 1 = 128 世界单位 = 一道悬崖面的高度。
- **斜坡(ramp)的额外提升**：若角点被"斜坡入口图块"覆盖且它是该图块里**最低层**的角点，则该角点高度 **+0.5 tile**（= +64 世界单位）。（`FinalGroundHeightWithRamp` **[项目]**）
- **斜坡入口判定**（`IsRampEntrance`）**[项目]**：图块的 4 个角点**全部**带 Ramp 标志，且层高不是"对角相等"（`bl==tr 且 tl==br` 则不是斜坡入口）——即必须存在一条对角层差，才构成可通行的斜坡。
- Undead03 实测层高与高度关系（中位数）：层 2→0.0、层 4→194、层 6→364、层 7→351 世界高度 **[存档]**。注意：**地面高度是连续量**，同一层内高度可跨 ±400 世界单位，因此**层号与高度不是一一对应**；层号用于网格/悬崖面生成，高度用于顶点位置。

## 4. 纹理拼接（接缝混合）—— 每图块 4 角组合打包 **[项目]**（HiveWE 权威）

### 4.1 每角点的"实际纹理" `RealTileTexture(x,y)`

先看**汇聚在该角点的 4 个图块**（`(x,y), (x−1,y), (x,y−1), (x−1,y−1)`）的标志：

```
aRomp = 任一图块的角点带 Ramp 标志
aCliff = 任一图块的角点带 悬崖(Cliff) 标志

若 aRomp 或 (aCliff 且 本角点不是 Ramp):
    → 取本角点"作者标注的悬崖纹理"(AuthoredCliffTexture)，
      经 CliffTypes.slk 的 groundTile 映射为该悬崖对应的地面纹理
      （若值 == 15 则减 14）
否则若 本角点 Blight:  → 最后一层（枯萎专用层 = 层数−1）
否则:                  → 本角点地面纹理
```

### 4.2 图块打包（4 个角点 → 4 个槽位）**[项目]**

```
bl, br, tl, tr = RealTileTexture(x,y), (x+1,y), (x,y+1), (x+1,y+1)
unique = 去重升序排列
槽0 = unique[0] * 32 + 变化索引(variation)        // 基底层
槽1..3 = unique[k] * 32 + 4 位掩码                // 混合层
    掩码: bit0 = br 是该纹理 ? 1 : 0
          bit1 = bl                  ? 2 : 0
          bit2 = tr                  ? 4 : 0
          bit3 = tl                  ? 8 : 0
空槽 = 60000.0
```

**含义**：一个图块最多叠加 **4 种不同地面纹理**；第 0 层是整块铺设的底色（带 deco 变化），其余各层用**角点掩码**只在对应的角点一侧显示——这正是"不同纹理接缝"的实现：接缝形状由图块内 4 个角点各自的纹理组合决定（16 种组合 → 16 个混合贴图单元）。

### 4.3 变化/装饰（variation）**[项目]**

```
若该纹理是"扩展纹理"(extended): 变化 ≤15 → 单元 16+变化；==16 → 单元 15；否则 0
否则(normal): 变化 == 0 → 单元 0；否则 → 单元 15
```
贴图集布局：**4×4 混合单元**，扩展图集在右侧再加 **4×4 变化单元**；每单元 64×64 RGBA8。

## 5. 悬崖拼接

### 5.1 悬崖面的生成依据 **[存档]** + **[项目]**

- 相邻角点**层号不同** → 该边生成**悬崖垂直面**，面高 = 层差 × 128 世界单位。
- 悬崖**外观（类型）**取自角点悬崖字节的高 4 位（本图 2 种：`CLdi`/`CLgr`），经 `TerrainArt/CliffTypes.slk` 映射到地面纹理、悬崖模型与过渡件 **[代码: 字符串 0x1412c2230 / 0x1412d4158]**。
- 悬崖在**图块级**做过渡：一个图块的 4 角悬崖层组合决定使用哪种悬崖过渡模型（含 `Doodads/Terrain/CityCliffTrans/*` 一类过渡件路径 **[代码: 字符串 0x1412e2d20]**）。

### 5.2 悬崖画笔如何"缝合"（写入规则）**[代码]**（细节见 `1.32-brush-water-texture-cliff.md`）
- 按下的角点层号作为目标层 `T` 抓取；必须落在 **[0, 15]** 内，否则整笔拒绝（不写任何东西）。
- 3×3 膨胀写入悬崖纹理；`cover` 时写 `L = T + 悬崖类型编号 + Rng.Next(8)`（8 = 悬崖变化数）。
- 抬升/降低一/两级 = `T ± 1`、`T ± 2`。

### 5.3 层→贴图的层高偏移 **[代码]**
```
纹理层高度偏移 = (纹理字节 & 0xf) * 128.0 − 256.0
```
用于把"角点实际高度"换算到所属层（1.32 的崖/坡高度范围计算 `FUN_140277a90` 里直接以它做上下界偏移）。

## 6. 水面拼接

| 项 | 规则 | 来源 |
|---|---|---|
| 水面存储 | 每角点一个 **绝对水面高度**（raw，8192 基准 = 高度 0），而非水深 | **[存档]** |
| 干/湿判定 | 水面高度 > 地面高度 → 该角点有水面；本图 20769/20777 角点有水面（几乎全图），水面 raw 9214–10466（≈ +255…+568 世界单位） | **[存档]** |
| 深/浅水 | 由"水深"驱动；浅水/深水笔刷改变的是**水面高度与地面的关系**（编辑器写入见刷子文档），并在有水面时改用 `TerrainArt/Water.slk` 的**按 tileset 水面偏移** | **[代码: 0x1412c5d28]** |
| 水陆过渡 | 走 §4.1 的 `RealTileTexture` 同一路径（水面本身是独立渲染层，地面纹理在该处通常取"浅滩/水边"纹理） | **[项目]** |

## 7. 枯萎 (Blight) 与地图边界

| 项 | 规则 | 来源 |
|---|---|---|
| Blight | 角点标志位；渲染时 **覆盖地面纹理**：`RealTileTexture` 命中 Blight → 使用**最后一层**专用贴图层（`层数−1`） | **[项目]**, **[存档]**（本图 13 个角点） |
| 画笔 | footprint + 半径 size+1 的环，按概率写入（1.27 为 30%），并会把地面纹理置 1 | **[代码: 见刷子文档]** |
| 边界 (MapEdge) | 角点水位字段的 **bit14**；地图最外圈角点由编辑器置位 | **[存档]**, **[代码]** |
