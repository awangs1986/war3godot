# 整平

> 参考实现：`src/HeightBrushes.cs（Plateau）` + `src/HeightPipeline.cs（Apply、SlopeClamp）`　对照结果：93/93（100%，第五轮前 91/93）（完整表格见 `../results.md`）

## 原理（1.27 源码 `0x57e700` op 2 + `0x57e3e0` 钳制）
1. 按下那一刻读中心角点高度 h0（存到 `this+0x948`），拖动全程都用它，所以能“推”出一块平台。
2. 覆盖集合内全部写成 h0，**没有衰减**；覆盖集合遵守形状（圆 / 方形）。
3. 写完后统一跑一次**坡度钳制**：MiscData 的 `MaxSlope=50`，相邻两角点高度差不能超过 tan50°·128 = 152.55 world = **610.2 raw**（对角 tan50°·181.02）。越界的点被夹回，再递归检查它的邻居。另有绝对上下限 MaxHeight=1536 / MinHeight=−128（world，按层级换算）。
以前文档写的“相机一侧边缘半施加、公式未定”是错的：那一圈就是钳制的结果，只是那次实验只有南侧坡度超限。

## 一步步的数值推演
`P2_base2` 上 s5（R = 4）整平，中心 (33,29) h0 = 9111：
1. 圈内 46 个点 → 9111，包括 d = 4 的 (33,25)（原 8583）。
2. 钳制按改动区包围矩形（外扩一圈）扫描，x 外层、y 内层。扫到 (33,24)（原 8415）：邻居 (33,25) = 9111，下限 = 9111 − 610.2 = 8500.8 → trunc → **8500**。
3. 再扫到 (33,25)：邻居 (33,24) 现在是 8500，上限 = 8500 + 610.2 = 9110.2 → **9110**。
4. 存档里正好是 8500 和 9110。如果按“每个改动点各自的小矩形”扫描，会先碰到 (33,25)，得到 9025 / 8415，对不上——扫描顺序也是算法的一部分。

## 对应代码
所有高度笔刷共用 `HeightPipeline.Apply`：①算新高度 → ②量化 trunc((world+2048)·4) → ③`SlopeClamp` → ④返回实际改动区（含被钳制波及的圈外点）。`Plateau` 只负责①（返回 h0）。浅水/深水也调用这个 `Plateau`。

## 验证范围
- h0、无衰减、坡度钳制：**1.27源码+1.32存档验证**（P2 的 8500/9110）。
- 方形整平、MaxHeight/MinHeight 绝对上下限：**仅1.27源码**。
- 钳制中的水相关下限：**仅1.27源码，未实现**。

## 常见误区（对照你现在的写法）
- 不要给整平加“边缘衰减”：边缘过渡来自全局的坡度限制，不是笔刷本身。
- 方形整平是有效的（1.27 源码确认；1.32 重制版未复测）。
- 钳制在 float32 世界单位里算，写回时 trunc((world+2048)·4)，所以 8500.8 → 8500。
- 未模拟：官方钳制里还有一段水相关的下限（`0x51dcb0/0x605fc0`）。
