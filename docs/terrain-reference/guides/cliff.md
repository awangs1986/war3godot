# 悬崖升降与传播（−2 / −1 / 同层 / +1 / +2）

> 参考实现：`src/CliffBrushes.cs:13-82（Cliff、Propagate）`　对照结果：单次 150/150（100%）；连点（cliff_repeat）77/81（95.1%，未变，原因见下）（完整表格见 `../results.md`）

## 原理（1.27 源码 `0x574470`、`0x573990`）
1. 按下时目标层 T = L(中心) + Δ，存到 `this+0x94c`，拖动全程用它。
2. **T < 0 或 T > 15 时整笔不执行**（拒绝，不是 clamp）。所以层 0 上点 −2 什么都不变。
3. 覆盖集合内写层级 T、悬崖类型、随机变体；3×3 外扩一圈也写悬崖类型和变体（`0x5748c0`）。
4. 传播（`0x573990`）：从改动区包围矩形的每个点出发，检查 8 个邻居，层差 > 2 就拉到“中心 ∓ 2”，**同时写入所选悬崖类型和随机变体**，再以被拉的点为中心递归（深度记在顶点字节 +0xb；笔刷点字节为 1，传播不会回头改它们）。

## 一步步的数值推演
层 2 平地，s1 同一点 +2 两次：
1. 第一次：中心 2 → 4，邻居是 2，差 2，合法，不传播。
2. 第二次：中心 4 → 6，8 个邻居差 4 > 2 → 拉到 4（并染成所选悬崖类型），再外一圈差 2，停止。
结果就是 6/4/2 的方锥（存档 `P_c+2_s1_x3`）。

## 常见误区（对照你现在的写法）
- 你的 `:458` 写的是 `k == 0 && l == 0`，应该是 `k == i && l == j`；`:462` 的 `(l − k)` 应为 `(l − j)`。
- **传播时要给邻居写悬崖类型**（第四轮文档说不写是错的；你的 `:457` 写类型是对的）。
- 目标越界不要 clamp 后照样执行，要整笔放弃。
- 用 4 邻接传播会得到菱形，官方是方形。
- 未模拟：官方每点还会按水夹到 [水决定的下限, 15]（`0x5764a0`），且夹后的值会改写 T。

## 关于 `P_c+2_s3_x3` 的 4 个不一致点
官方结果在南侧多出一行（(31,33) 为 6、(30..32,34) 为 4），北侧没有对应的一行，形状不对称。原地点 3 次在 1.27 的逻辑里一定是对称的，所以这是实验时某次点击光标向南偏了一格（第四轮已知光标会落到抬高的地形上）。不是算法差异，保留原样作为提醒。
