# 悬崖升降与传播（−2 / −1 / 同层 / +1 / +2）

> 参考实现：`src/CliffBrushes.cs（Cliff、Propagate）`　对照结果：单次 150/150（100%）；连点（cliff_repeat，层级+悬崖类型）158/178（命中点未记录，见下）（完整表格见 `../results.md`）

## 原理（1.27 源码 `0x574470`、`0x573990`）
1. 按下时目标层 T = L(中心) + Δ，存到 `this+0x94c`，拖动全程用它。
2. **T < 0 或 T > 15 时整笔不执行**（拒绝，不是 clamp）。【仅 1.27 源码：1.32 存档两种解释都成立】所以层 0 上点 −2 什么都不变。
3. 覆盖集合内写层级 T、悬崖类型、随机变体；3×3 外扩一圈也写悬崖类型和变体（`0x5748c0`）。
4. 传播（`0x573990`）：从改动区包围矩形的每个点出发，检查 8 个邻居，层差 > 2 就拉到“中心 ∓ 2”，**同时写入所选悬崖类型和随机变体**，再以被拉的点为中心递归（深度记在顶点字节 +0xb；笔刷点字节为 1，传播不会回头改它们）。

## 一步步的数值推演
层 2 平地，s1 同一点 +2 两次：
1. 第一次：中心 2 → 4，邻居是 2，差 2，合法，不传播。
2. 第二次：中心 4 → 6，8 个邻居差 4 > 2 → 拉到 4（并染成所选悬崖类型），再外一圈差 2，停止。
结果就是 6/4/2 的方锥（存档 `P_c+2_s1_x3`）。

## 常见误区（对照你现在的写法）
- 你的 `:458` 写的是 `k == 0 && l == 0`，应该是 `k == i && l == j`；`:462` 的 `(l − k)` 应为 `(l − j)`。
- **传播时要给邻居写悬崖类型**（第四轮文档说不写是错的；你的 `:457` 写类型是对的）。
- 目标越界不要 clamp 后照样执行，要整笔放弃。
- 用 4 邻接传播会得到菱形，官方是方形。
- 未模拟：官方每点还会按水夹到 [水决定的下限, 15]（`0x5764a0`），且夹后的值会改写 T。

## 连点用例：命中角点没记录，结论是**未证实假设**
- 现在连点测试同时比较层级和悬崖类型（第五轮之前只比层级）。
- `P_c+2_s1_x3`：按“3 次都点 (31,31)”算，悬崖类型对不上（官方 3×4，参考 5×5）。在 5×5 偏移里穷举 3 次点击，**唯一**能让层级 + 类型全对的是“第 1 次 (31,32)，后 2 次 (31,31)”。`cases.json` 里用这个推断序列，所以它的 21/21 **不算验证**，只说明假设自洽。
- `P_c+2_s3_x3`：3 次点击在 ±2 内穷举，最好仍差 10 个字段；按原地 3 次算差 20 个（4 个层级 + 16 个悬崖类型），南侧多出两行。可能是拖动、多施加了一次，或光标漂移。**未证实**，不要据此改算法。

### 重做实验：逐次记录真实命中角点
1. 每次点击前存一份：`drv.saveas('cr_k0')`；点击一次后立刻 `drv.saveas('cr_k1')`，依此类推（每次只点一下，不拖动，点完松开再移动）。
2. 对相邻两份做差分：`python3 w3e.py maps/cr_k0.w3m maps/cr_k1.w3m`。层级改动区（或悬崖类型改动区）的中心就是这次的命中角点，记到 `cr_hits.txt`（格式 `k x y`）。
3. 中心不唯一时（例如目标层与原层相同、改动为空），这次点击记为“无效”。
4. 把记录的序列写进 `cases.json` 的 `clicks` 字段（相对 cx,cy 的偏移），再跑对照。只有这样得到的结果才能写成“1.32 存档验证”。
