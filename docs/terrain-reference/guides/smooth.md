# 平滑

> 参考实现：`src/HeightBrushes.cs:65-80（Smooth）`　对照结果：106/111（95.5%）：Shift 49/49；普通 57/62，不一致的都只差 1 raw（完整表格见 `../results.md`）

## 原理
平滑是“向周围平均靠拢”。官方用**施加前的快照**算 9 点平均（自己 + 8 个邻居），普通模式 h' = floor(0.8·h + 0.2·avg9)，Shift 模式 h' = floor(h + 0.05·avg9)。Shift 的权重和是 1.05，不归一化，所以它其实在放大起伏。
**这是第四轮的更正**：之前文档写的是 8 邻平均，对照存档只有 50–65% 对得上；改成 9 点平均 + 向下取整后才对上。

## 一步步的数值推演
`b2_smooth_s3` 角点 (31,31)（高度相对 8192）：
1. 9 个点：812, 859, 849, 871, **919**, 909, 872, 919, 909，和 = 7919，avg9 = 879.89。
2. 0.8 × 919 + 0.2 × 879.89 = 735.2 + 175.98 = 911.18 → floor → **911**，与存档一致。
3. 如果用 8 邻平均：(7919 − 919)/8 = 875 → 0.8×919 + 0.2×875 = 910.2 → 910，**差 1**。这就是之前 8 邻公式对不上的原因。
4. 角点 (32,31)：avg9 = 869.0，0.8×909 + 0.2×869 = 901.0 → 901，一致。
少数点（5/111）差 1 raw，推测是官方内部用 32 位浮点，901.0 这类“刚好整数”的值会因误差落到两边。

## 常见误区（对照你现在的写法）
- 你的 `:377` 用 0.97/0.03：强度只有官方的约 1/7。
- `:368-373` 边扫描边写，用的是实时值：匹配率会掉到 50% 左右（实测过）。
- 把高度直接用 8192 起点去乘权重，会把整片地形抬高。
