# 平滑

> 参考实现：`src/HeightBrushes.cs（Smooth）` + `src/HeightPipeline.cs`　对照结果：111/111（100%，第五轮前 106/111）（完整表格见 `../results.md`）

## 原理（1.27 源码 `0x57e700` op 4）
1. 先把整个覆盖区的新值算进一块缓冲（`this+0x1c4`），全部算完才写回——等价于“用施加前的快照”。
2. 每点用 3×3 核加权平均邻居，**中心权重是 0**：
   ```
   1 2 1
   2 0 2      avgK = Σ(k·h) / Σk   （Σk = 12；地图边缘缺的邻居不计入分母）
   1 2 1
   ```
3. new = trunc(W1·h + W2·avgK)。普通 W1=0.80、W2=0.20；Shift W1=1.00、W2=0.05（WorldEditData.txt 的 `SmoothBrushWeights*`）。全程 float32。
4. 覆盖集合遵守形状；写完走同一条流水线做坡度钳制（见整平）。

验证范围：1-2-1 核与权重 **1.27源码+1.32存档验证**；方形平滑 **仅1.27源码**。

**第五轮更正**：第四轮的“9 点平均”是黑盒拟合出来的近似（92%），差 1 raw 的点不是浮点误差，而是公式本身不对。Shift 的权重和是 1.05，不归一化，所以它其实在放大起伏。

## 一步步的数值推演
`b2_smooth_s3` 角点 (31,31)，3×3 高度（相对 8192）：

1. 四角 ×1：812+849+872+909 = 3442；四边 ×2：(859+871+909+919)×2 = 7116；和 10558，avgK = 879.83。
2. 0.8 × 919 + 0.2 × 879.83 = 735.2 + 175.97 = 911.17 → trunc → **911**，与存档一致。

## 常见误区（对照你现在的写法）
- 你的 `:377` 用 0.97/0.03：强度只有官方的约 1/7。
- `:368-373` 边扫描边写，用的是实时值：匹配率会掉到 50% 左右（实测过）。
- 把自己也算进平均（9 点平均）或用等权 8 邻：都只是近似，会差 1 raw。
- 把高度直接用 8192 起点去乘权重，会把整片地形抬高（官方先换成 world = raw/4 − 2048）。
