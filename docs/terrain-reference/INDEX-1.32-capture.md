## ⚠ 两处命名冲突的消解（重要）

同一个数值区间 **0..4** 在两个**不同枚举**里都出现，两篇文档各取其一，并不矛盾：

1. **高度刷 op（`FUN_140276110` 的 `param_2`）**：0=升高、1=降低、2=整平、3=噪化、4=平滑 ——
   依据：算法形状（`cosf` 步进 / 目标置高 / `rand` / 3×3 加权均值）+ 调色板字符串映射 `WESTRING_BRUSH_RAISE/LOWER/PLATEAU/NOISE/SMOOTH`（`0x14029acdd`）。
2. **动作分派（`FUN_14017c850` case 6 的 action id）**：0..4 = 悬崖层 ±2/±1/0；5/6 = 深/浅水；7 = 斜坡；另按 tag 走 `BLIG`→枯萎、`NOTH/NOTR`/纹理 id → 纹理 ——
   依据：`FUN_14017c850` 的 switch 与各组调色板的 tag。

**结论**：`FUN_140276110` 只被 5 个高度刷调用（其 `param_2` 是高度 op）；悬崖/水/斜坡/纹理/枯萎走**另一条**分派链。若要铁证：在 `FUN_140276110` 入口断点，逐个点选调色板按钮读 `edx`（未做，标 **[未测]**）。

## 记录布局（两文一致，最简版）

```
corner = [map+0x188] + idx*0x1C        idx = y*([map+0xf4]+1) + x
+0x00 u32 : bit0-13 地面高度 raw；bit14-22 = X 序号(x − width/2 + 256)；bit23-31 = Y 序号
+0x04 u32 : bit0-17 角点 idx；bit18-31 水位 raw（8192 基准）
+0x08 u8  : 低4 = 地面纹理槽
+0x09 u8  : 低5 = 悬崖纹理 id；bit5-6 = Rng(0,3)
+0x0a u8  : 低4 = 层/崖层级；高4 = 悬崖类型索引
+0x0b u8  : 笔刷命中/后处理深度标记（1=op 写，2=坡度修正，>2=递归层；收尾清零）
+0x0c u16 : bit0 纹理刷禁止 / bit1 ramp / bit2 blight / bit4 water / bit6 边界瓦 / bit7 地图边界 / bit8-9 可枯萎缓存
+0x10/14/18 3×f32 : 法线辅助
```
